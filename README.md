# מערכת ניהול בית ספר: שרת (Backend)

שרת API למערכת ניהול בית ספר: התחברות, הרשאות לפי תפקיד, כיתות, מקצועות, שיבוצי מורות, תקופות ציון, מבחנים וציונים (כולל חישוב ציון תקופה ושנתי), נוכחות, מערכת שעות, הודעות, ברכות יום הולדת לפי התאריך העברי, ייצוא לאקסל וייבוא תלמידות מאקסל.

> **מתחילה עכשיו?** פתחי את [START-HERE.md](START-HERE.md). שם יש הוראות צעד אחר צעד להעלאה ל־GitHub ולענן.
> **כותבת את צד ה־React?** פתחי את [FRONTEND-API-GUIDE.md](FRONTEND-API-GUIDE.md).

---

## טכנולוגיות

| תחום | כלי |
| --- | --- |
| שפה וסביבה | Node.js 22 (LTS), TypeScript במצב strict |
| שרת | Express 5 |
| מסד נתונים | PostgreSQL + Prisma ORM 6 (מנוע JavaScript דרך ספריית pg, בלי קבצים בינאריים בזמן ריצה) |
| ולידציה | Zod 4 |
| התחברות | JWT (jsonwebtoken), הצפנת סיסמאות ב־bcrypt (bcryptjs) |
| תיעוד | Swagger UI / OpenAPI 3 בכתובת `/api-docs` |
| בדיקות | Vitest + Supertest |
| קבצים | ExcelJS (אקסל), Multer (העלאת קבצים) |
| תאריך עברי | @hebcal/core |

אין שימוש בשירותי AI או בשירותים בתשלום. הפרויקט עובד באופן עצמאי.

## משתמשות ותפקידים

| תפקיד | קוד | מה רואה |
| --- | --- | --- |
| מנהלת | `PRINCIPAL` | את כל בית הספר שלה בלבד: כיתות, מורות, תלמידות, שיבוצים, ציונים, נוכחות, הודעות |
| מורה | `TEACHER` | רק את השיבוצים שלה (מקצוע + כיתה): מבחנים, ציונים, נוכחות, מערכת השעות שלה |
| תלמידה | `STUDENT` | רק את עצמה: הציונים שלה, הנוכחות שלה ומערכת השעות של הכיתה |

- אין הרשמה עצמית. המנהלת פותחת חשבונות.
- אחיות יכולות לחלוק מייל של ההורים. ההתחברות היא מייל + סיסמה, ולאותו מייל אסור שתהיינה שתי סיסמאות זהות.
- כל הנתונים שייכים לבית ספר. השרת מזהה את בית הספר מתוך ה־Token, ולכן מנהלת אחת לא רואה בית ספר אחר.
- בית ספר חדש נוסף בפקודה `npm run create-school` (ראי למטה).

## הרצה במחשב

צריך: [Node.js 22 LTS](https://nodejs.org) ומסד נתונים PostgreSQL. הכי פשוט: מסד נתונים חינמי ב־Neon (ההסבר ב־START-HERE.md, חלק ב). לא צריך להתקין PostgreSQL או Docker.

```bash
npm install                 # התקנת התלויות
cp .env.example .env        # ואז למלא את הערכים בקובץ .env
npm run db:deploy           # יצירת הטבלאות (Migrations)
npm run db:seed             # נתוני הדגמה (מוחק נתונים קיימים!)
npm run dev                 # הפעלת השרת עם רענון אוטומטי
```

השרת עולה בכתובת `http://localhost:3000`, והתיעוד בכתובת `http://localhost:3000/api-docs`.

## נתוני ההדגמה

**בית יעקב 'עטרת שרה'** (בני ברק, נתונים מומצאים): כיתות ד'1, ד'2, ה'1, ה'2 עם 22-24 תלמידות בכל כיתה, 9 מורות, 8 מקצועות (חומש, נביא, דינים, לשון, חשבון, אנגלית, טבע, ידיעת הארץ), מערכת שעות שבועית מלאה, מבחנים וציונים ממחצית א' של תשפ״ז, נוכחות מתחילת השנה, הודעות, ומשפחות עם אחיות שחולקות מייל.

**בית ספר לבנות 'בית חנה'** (קטן): נועד להראות שמנהלת לא רואה בית ספר אחר.

כמה דברים להדגמה:
- **דינים**: מחצית א' הושלמה (100%), ולכן יש ציון מחצית. מחצית ב' עוד ריקה, ולכן אין ציון שנתי, והשרת מסביר למה.
- **ידיעת הארץ**: קורס של סמסטר אחד (סמסטר א' 100%, סמסטר ב' 0%), ולכן יש גם ציון שנתי.
- שאר המקצועות: שני מבחנים כבר נערכו, ומבחן המחצית בעתיד.
- תלמידה אחת בד'1 מקבלת יום הולדת עברי ביום שבו נוצרו הנתונים.

## הוספת בית ספר חדש

כשמנהלת פונה ומבקשת להצטרף, מריצים במחשב (עם `DATABASE_URL` של מסד הנתונים בענן בקובץ `.env`):

```bash
npm run create-school -- --name "בית יעקב החדש" --city "אלעד" --first "מרים" --last "שפירא" --email "menahelet@example.com" --subjects "חומש,נביא,חשבון"
```

הפקודה מדפיסה סיסמה זמנית פעם אחת. המנהלת נכנסת, מוסיפה כיתות, מורות ותלמידות (או מייבאת מאקסל), ומשנה את הסיסמה.

## אבטחה

- סיסמאות נשמרות כ־Hash של bcrypt בלבד. לא Hash ולא סיסמאות מוחזרים ב־API.
- כל נתיב (חוץ מ־`/api/health` ו־`/api/auth/login`) דורש `Authorization: Bearer <token>`. בלי Token או עם Token לא תקין או שפג תוקפו: 401. בלי הרשאה: 403.
- המשתמשת והתפקיד נקבעים מה־Token ומהמסד, לא ממה שהלקוח שולח. משתמשת שהושבתה מאבדת גישה מיד.
- הפרדה בין בתי ספר: רשומה של בית ספר אחר מחזירה 404.
- הגנה מניחוש סיסמאות: אחרי 10 ניסיונות כושלים, חסימה ל־15 דקות.
- CORS מוגבל לכתובות שבמשתנה `CORS_ORIGINS`, ו־Helmet מוסיף כותרות אבטחה.
- בענן, חשבונות ההדגמה נוצרים רק עם סיסמה שהוגדרה במשתנה סביבה, והסיסמאות לא נכתבות ליומן השרת.
